# three-kingdoms-strategy · 三国志

> DeepSeek Harness 插件 —— 复刻 2007–2009 年诺基亚 J2ME 手机上那个三国志：
> 八城地图、内政、征兵、出征，**智力定计略、武力决胜负**。

---

## 它是什么

一个悬浮在 DSH 界面右下角的完整回合制战略游戏。点开即玩，不需要开新窗口、不需要启动别的服务。

```
189 董卓乱政 / 200 官渡之战 / 207 卧龙出山 / 214 益州既得
                    ↓ 选一个年代
                     ↓ 再选一方势力
  地图（八城）→ 城池（开垦/商业/征兵/训练/筑城/招募）
                    ↓
              出征（火攻/伏兵/离间/强攻）→ 战报
                    ↓
                 结束本月 → AI 行动
```

## 为什么是「霸王的大陆」那一套

07–09 年的诺基亚三国游戏，内核基本都来自 90 年代的《三国志 II 霸王的大陆》。它和后来的三国志最大的区别是：

**智力不是一个「文官属性」，而是战术兵器。**

- **武力**决定正面交战时每回合打出多少伤害
- **智力**决定你能不能放计略、放得成不成
- **统率**决定这个人最多能带多少兵（统率 × 400）

所以诸葛亮（武 38 / 智 100）在单挑里是废物，但一个火计能把守军烧掉 5,280 人。而张飞（武 98 / 智 30）根本点不动火攻按钮 —— 智力不足 80，游戏会直接拒绝：

```
张飞 智力不足以施展火攻。
```

这不是提示后照常结算，是**真的不能用**。智力门槛是真的门槛。

## 计略

| 计略 | 门槛 | 效果 |
|---|---|---|
| **火攻** | 智力 ≥ 80 | 按智力差算成功率，命中则守军大损。诸葛亮必中且伤害翻倍 |
| **伏兵** | 智力 ≥ 60 | 命中则守军前三回合攻势减半 |
| **离间** | 智力 ≥ 70 | 命中则守军士气大跌、城防打折 |
| **强攻** | 无 | 不用计略，正面硬撼 |

火攻成功率 = `0.42 + 智力差 × 0.009`，夹在 10%–95%。诸葛亮固定 100%。

实测诸葛亮火攻长安：

```
诸葛亮 引兵 12,000 自 成都 出兵，直取 长安。
守将 徐晃（武 88 / 智 60）闭城坚守，守军 11,000，城防 72。
火计必中！诸葛亮 祭起东风，长安 城中烈焰冲天，守军折损 5,280。
夏侯惇 单骑突围，不知所终。
徐晃 力竭被擒，愿降。
刘备军 取 长安（原属 曹操军），余兵 9,475。
```

## 四个年代

年代不是换个背景色，是**换整张地图的归属**：

| 年代 | 格局 | 可用势力 |
|---|---|---|
| **189 董卓乱政** | 董卓挟天子据洛阳长安，袁绍据邺，曹操仅许昌一城，刘备尚无寸土 | 6 家 |
| **200 官渡之战** | 曹操四城对袁绍河北，两雄相持 | 4 家 |
| **207 卧龙出山** | 默认开局。曹操已并河北，刘备孙权偏安 | 3 家 |
| **214 益州既得** | 刘备得蜀，关羽镇襄阳，孙权孤悬江东 | 3 家 |

**武将按生卒年自动进出场。** 189 年没有陆逊（才 6 岁），207 年没有吕布（已死 8 年），214 年周瑜病故。不用手写四份武将表：

```
189: 吕布 董卓 袁绍 颜良     -陆逊 诸葛亮 -司马懿
207: -吕布 -董卓 -袁绍 -颜良  陆逊 诸葛亮  司马懿
```

武将的**势力归属跟着他驻守的城池走**。张辽在 189 年守邺城（袁绍的），就是袁绍部将；在 207 年守邺城（曹操的），就是曹操部将。同一份武将表，不用维护四遍。

## 上手

安装：

```bash
# 从 GitHub
dsh plugin --profile desktop add zhanghao3693/dsh-three-kingdoms

# 或从本地目录
dsh plugin --profile desktop add /绝对路径/three-kingdoms-strategy
```

`--profile` 是必需参数，`desktop`（Electron GUI）和 `web` 都可以，省略会报
`required option '--profile <name>' not specified`。

装完刷新页面，右下角出现一个金色的「三」字圆钮，点开就是游戏。

游戏内：

1. **选年代 → 选势力**（三个难度档已标在势力卡上）
2. **点城池** → 内政五项（每城每月限 1 次）+「招募」「出征」
3. **出征**选目标城、出阵武将、兵力、计略
4. **结束本月** → AI 行动 → 下个月

存档自动写 localStorage，关掉页面再打开还在。点「重开」回到选年代界面。

## 一些实现细节

**全客户端。** 宿主侧 `index.js` 是个空壳 `export function apply() {}`，不持有任何状态、不开任何接口。所有逻辑（地图、内政、战斗、AI、存档）都跑在浏览器里。这意味着它不挑 profile —— `web` / `desktop` 都能用，也不需要 `webServer`。

**AI 不赖皮。** AI 和玩家受同一套规则约束：每城每月一次内政、同一套伤害公式、同一套城防加成。唯一的偏置是 `AI_DRAFT_THRESHOLD = 14000` 的征兵上限（玩家受统率上限约束可达 40000）—— 这是故意留的，否则 AI 会滚雪球到玩家无解。

**纯函数内核。** `createGame` / `doDomestic` / `doRecruit` / `doBattle` / `endTurn` / `loadGame` / `saveGame` 全部是接收 state 返回新 state 的纯函数，React 只负责渲染。所以整个游戏可以在 Node 里无头跑完几千局做平衡测试 —— 上面那张难度表就是这么来的。

**出征有四道守卫。** `doBattle` 是导出的纯函数，任何调用方都能传任意参数，所以它在内部拦：打自己、打友军、打不相邻的城、武将不在出发城。

## 结构

```
three-kingdoms-strategy/
├── package.json          # dsh.bundle.patch 声明，缺了会「装成功但没反应」
├── cordis.patch.yml      # insert 到 profile layer 栈，id 必须等于 index.js 的 name
├── index.js              # 宿主入口，空壳
├── client.js             # 全部游戏逻辑与 UI（1905 行，零依赖）
└── icon.svg
```

`client.js` 通过 `window.__ModuleLoader__.load()` 注册，把组件注入 `shell.overlay` 槽位（DSH 的全框浮动层，click-through，条目自己 opt-in 指针事件）。
